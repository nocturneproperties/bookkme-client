# Bookk website (`apps/site/`)

Kobweb (Kotlin/JS, Compose HTML + Silk) website on `bookkme.com`. The client web app (the Telegram Mini App) is a separate Kobweb app on its own host, `:client` in `apps/client/` (see [`apps/client/README.md`](../client/README.md)); this file also holds the web design system and JS-runtime guidelines both apps share. The domain layer, `core:presentation` and the shared `designsystem` state interfaces also compile for JS; the web state implementations and components live in `:designsystem`'s `jsMain`.

This file holds the web-only guidelines. The project-wide rules in the root `AGENTS.md` (architecture, layer boundaries, no comments, block bodies, strings and translations, testing) apply here too, and its **Web target** section lists the JS-target rules shared with mobile work.

## Commands

- **Run the website**: `./gradlew :site:kobwebStart -t` (http://localhost:8080, or the `Site` run configuration), stop with `./gradlew :site:kobwebStop`. The site calls no API, so it needs no `-Pbuildkonfig.flavor`.
- **Run JS tests**: `./gradlew jsNodeTest` (web-target modules' `commonTest` + `jsTest` on Node.js; one module: `./gradlew :<module>:jsNodeTest`)

## Layout

- `apps/site/`: the `:site` application. Static files in `src/jsMain/resources/public/`, copy in `src/commonMain/moko-resources`. Code in `src/jsMain/kotlin/me/bookk/site/` is grouped by page area, not by kind of code:
  - `pages/`: only the thin Kobweb `@Page` files (file routing derives the URLs from this package), which compose sections from the area packages.
  - `layout/`: the frame around every page: `PageLayout` (+ `PageLayoutData`, `PAGE_LAYOUT_ID`), `NavHeader`, `Footer`, `Logo`, `NotFoundMessage`. Pages refer to the layout as `@Layout(".layout.PageLayout")`; moving it means updating those annotations and `PAGE_LAYOUT_ID`.
  - `navigation/`: `SiteNavigation` (origin, paths, link lists), `LocalizedRoutes`, `LanguageRedirect`.
  - `landing/`: building blocks shared by the landing pages (and Contact): `LandingSections`, `LandingSection` anchors, `KeyDiagram`, `Feature`. Area-specific content and sections live in `landing/business/` (`/`: `BusinessContent`, `BusinessSections`, `StepSnippets`) and `landing/clients/` (`/clients`: `ClientContent`, `ClientSections`). Shared blocks take their data as parameters and never read a business or client content object.
  - `contact/`: `ContactContent`, `ContactChannelRow`.
  - `legal/`: the legal-text model and `LegalPages` builder, with `legal/markdown/` (the parser) and `legal/ui/` (the composables and the legal pages' `@InitRoute` helper).
  - A new page area gets its own package holding its content object, model classes and sections.
- `apps/site/domcompat/`: the DOM symbols `kotlinx-browser` lacks (`:site:domcompat`, see **DOM API** below).
- `library/telegram/`: the Telegram Mini App SDK (`:library:telegram`), used by the client web app; see [`apps/client/README.md`](../client/README.md).
- `apps/site/legal/`: published legal texts (see [`legal/README.md`](legal/README.md)).

The JS-only modules (`:site`, `:client`, `:site:domcompat`, `:library:telegram`) apply `convention.kmm.web` instead of the bare Kotlin Multiplatform plugin. It applies Kotlin Multiplatform with the shared compiler options (`applyCompilerOptions()` in `KotlinConvention.kt`, e.g. `-Xexpect-actual-classes`) but no Android/iOS targets or dependencies. Put compiler flags every module needs in `applyCompilerOptions()`, not in a module's build script.

## Shared code on the JS target

- Room on JS runs SQLite WASM in a module Web Worker that the client web app serves; see [`apps/client/README.md`](../client/README.md).
- DataStore on JS (`:library:cache:impl` `jsMain`) uses `WebLocalStorage` wrapped in `DataChangeStorage`. DataStore 1.3.0 bumps the version key before it writes the data and only listens for the version key, so other tabs re-read stale data. `DataChangeCoordinator` notifies on the data key's `storage` event instead, which keeps open tabs in sync live. Do not switch to `WebOpfsStorage`: in 1.3.0 a tab can read its own just-written value back stale.
- `jsMain` actuals are built on the browser's `Intl` APIs where the other platforms use ICU/Foundation (`JsDateLocalizer`, `JsTextCollator`, `startOfWeek`, `Currency`). `core:presentation`'s `ViewModel` is a commonMain class over `expect abstract class PlatformViewModel` (Android: androidx `ViewModel`; iOS/JS: its own scope and a public `onCleared()`). Web screens get their ViewModel with `rememberViewModel<T>(key) { parametersOf(...) }` from `core:presentation`'s `jsMain`, the counterpart of `koinViewModel`: it resolves it from Koin and calls `onCleared()` when the screen leaves the composition. Inside a `BackStackHost` (`:designsystem`, rendering a `BackStack` from `core:presentation`'s `jsMain` `navigation/`), it takes the ViewModel from its entry's `ViewModelStore` (provided through `LocalViewModelStore`) instead, so a screen covered by another keeps its ViewModel and is cleared only when its entry has been popped and has finished sliding away, or when the stack leaves the composition. Test JS-only behavior in `jsTest`.
- `:library:device:impl`'s `JsDeviceFacade` reports the platform `web`, `navigator.language` as the locale (the `Accept-Language` of API calls) and no currency (`CreateBusiness` falls back to its default). The device name comes from the user agent through `BrowserDeviceName` (`Chrome on Android`, `iOS` for an in-app web view, `Web browser` otherwise). Links open in a new tab, `tel:`/`mailto:` replace the current location, `share` opens the Web Share API sheet (or copies the text to the clipboard where the browser has none), and `openAppSettings` does nothing because a page cannot open browser settings.
- `:core:data`, `:feature:authorization:data`, `:feature:settings:data`, `:feature:business:data`, `:feature:appointments:data` and `:feature:employees:data` build for JS (Ktor's JS client, which adds the `ws` npm package). Only the client web app starts Koin and calls the API; how it does (`initClientApp()`, `ClientAppTest`, BuildKonfig flavors, the web passkey stub) is in [`apps/client/README.md`](../client/README.md). Each Kobweb app is one script with no per-route code splitting, so everything any page's init can reach is in every page's download: that is why the client stack lives in its own app instead of a site route.
- JS formatting follows `StringDesc.localeType` (set by the site's language picker); with `LocaleType.System` it falls back to the browser default.
- kotlinx-datetime on JS only knows the system zone unless `@js-joda/timezone` is loaded; `:core`'s `jsMain` (`me.bookk.core.time.JsJodaTimeZone.kt`) does that for every consumer — do not remove it. It loads the `js-joda-timezone-60-year-range` bundle (± 30 years around the year the data was generated, 1996–2056 for the 2026 data), not the full one: on the first `TimeZone.of` kotlinx-datetime builds the rules of every zone in the loaded data with emulated `Long` arithmetic, which with the full history blocked the page's main thread for seconds (and with it the start of every worker). Outside the range offsets are silently wrong; `TimeZoneSerializerTest` (`:core:data`) pins Warsaw's DST thirty years either way, so a narrower bundle fails it.
- JS tests run on Node via `jsNodeTest` (browser test tasks are disabled). moko's generated JS code loads string files with `require("./localization/*.json")`, which only webpack can resolve; `runUnitTest` calls the JS `prepareTestEnvironment()` in `core:testFixtures` to emulate it for strings (`.json`) and images (`.svg`, `.png`, resolved to their file path like webpack's asset loader), so moko resources work in Node tests. A module whose JS tests touch moko resources must apply the moko plugin (it copies the JSON files into the test package).

## Web design system (`:designsystem` `jsMain`)

- `:designsystem`'s `jsMain` (package `me.bookk.designsystem`, beside the Android components in `androidMain`) holds the web counterparts of `designsystem/androidMain` and the Swift design system: `Web*State` implementations of the shared state interfaces (`uistate/`), Silk/Compose HTML components that render them (`components/`: `ActionButton`/`TextButton(ButtonState)`, `StateText`, `TextBlock`, `Heading`, `Header`, `AppCard`, `TitledCard`, `AccentTitledBlock` (a title under a short accent rule, no container), `TextList`, `HorizontalDivider`/`VerticalDivider`, `StateSwitch`/`CheckBox(BooleanState)`, `RadioButton`, `TextField` (a bold 15px (0.9375rem) secondary label over a filled Silk `Input` drawn like the cards: `Elevated`, no border until focused in `ActionText` or invalid in `Error`, 3.5rem tall with 1rem padding, radius and font size, `HintText` placeholder; `minLines` > 1, like Android's `minLines` and iOS's `lineLimit`, draws a `<textarea>` with the same Silk filled input style, at least that many lines tall and growing with its text where the browser supports `field-sizing: content`), `List(ListState, key)` and `CardList(ListState, key)` (the same states, its rows in one `AppCard` between dividers), `CardGrid(ListState, key)` (the same states, each item its own card in a grid of columns at least 8rem wide, two on a phone) with empty/error/banner views (rows are keyed, and a row added after the list first showed content fades and slides in through `AppearingItem`/`rememberItemAppearance`, which `OptionsQuantityList` uses too; the rows of the first content and of a screen returned to do not animate) (an initial-load error wins over the loading spinner; `BannerErrorView` matches the apps' banner: a full-width strip on a 12% `Error` tint with the outlined Material warning icon, one ellipsized line of label-size error text and a semibold "Retry" text button, replaced by a small error-coloured spinner while retrying) (`EmptyStateView` matches the apps: an outlined Inbox icon over the label in the secondary colour; like Android and iOS it ignores `EmptyState.image`), `AppTopBar` (renders nothing when a small bar has no title, back arrow or action, e.g. inside Telegram where the back button is native), `NavigationBar` (sticky translucent header that expands to a full-height menu below a breakpoint) with `NavigationMenuButton`, `ObserveNavigation`, `LanguagePicker`, `ColorModeButton`, `IconButton`, `TextLink`, `ButtonLink` (a link drawn as a filled or tonal button), `SegmentedLinks` (a pill switch of links whose selected pill slides between equal segments, used for the For business / For clients switch; the header stays mounted across pages, so the slide plays on navigation), `Band` (a full-width section painted in a `BandTone`: `PLAIN` is the page background, `ALTERNATE` the elevated colour, `DARK` always renders in dark mode through a Silk `Surface` override; landing pages alternate them instead of tinting panels; `isCompact` halves the vertical padding for short strips such as Contact's "Before you write") with `BandSurface` (the same band without the content column, for full-bleed content) and `SectionContainer` (the `ContentMaxWidth` 72rem column shared by the header, sections, page layout and footer), `MediaPlaceholder` (a phone frame, browser frame or panel showing a label until real screenshots exist), `CardGallery` (a horizontally scrolling, snapping row of cards that runs to the page edge, with dots and previous/next buttons; `GalleryPosition` turns the scroll metrics into the selected dot and the enabled buttons), `DividedRows`/`DividedRow` (rows between thin dividers that wrap on narrow screens, used for the opinions on the landing page and the channels on Contact), `StepCard`, `TintedIcon` (a moko SVG masked in a `ColorToken`), `IconTile` (a `TintedIcon` on an accent-tinted rounded square), `DateTile` (a weekday and day number on the same accent tint), `StatusPill(text, ColorToken)` (a dot and label on a 16% tint of the token), `InfoNote(text, title = null)` (the apps' info note: the outlined Material info icon in `ActionText` beside an optional semibold title and the text, both in body-medium size, on a 20% `ActionText` tint with large rounded corners), `CardButton` (an elevated card that is one `<button>`, for tappable list cards), `SelectableCardButton(isSelected, isEnabled)` (an elevated card button with centred content, outlined in `ActionText` and `aria-pressed` while selected, for picking one card of a `CardGrid`, one day of a week strip or one time chip; `isEnabled = false` makes it a dimmed `disabled` button without hover or press effects), `NativeDatePicker(DatePickerState)` (with `WebDatePickerState`: a transparent `<input type="date">` laid over the control that opens it, placed together with that control in a relatively positioned box, with its calendar indicator stretched over the whole input, so a tap or click on the control lands on the input and opens the browser's own picker natively. `showPicker()` alone is not enough: browsers reject it in cross-origin iframes such as Telegram Web's, and a scripted click never opens a date picker. The input is out of the tab order and hidden from assistive technology, so keyboard users reach the control itself; when its action sets `isDatePickerVisible`, the picker opens through `showPicker()` (focus and click where it is missing) and the flag resets. It carries `minDate`/`maxDate`/`pickedDate` and calls `onDatePicked` once the picker closes: iOS and iPadOS change the value on every tap inside the open picker, so there `DatePickerCommit` (`DateCommitMode.ON_CLOSE`, chosen from the user agent and touch points) holds the date until the input loses focus, while other browsers already change it only as the picker closes (Android on OK, desktop popups on the click that picks a day) and commit on `change`; its 1rem font size keeps iOS from zooming in on focus) and `ListRowButton` (a borderless row button ending in a chevron, for rows inside an `AppCard`), `InitialsAvatar` (a person's initials in an accent-tinted circle, beside their name; `InitialsAvatarSize.LARGE` on a card), `NumberedSteps` (an ordered list of numbered steps on an elevated card), `RevealingBottomBar(value) { }` (a bar stuck to the bottom of the page on the background colour with a divider above it, shown while `value` is not null: its panel slides up from below the bar's clipped box (280 ms, decelerating) and slides back down when `value` turns null (220 ms, accelerating, so the exit is visible from its first frame), still drawing the last value as it leaves. It only slides: animating `grid-template-rows` between `0fr` and `1fr` clips the item to fr × fr of the row and a decelerating fade is half gone in the first frame, so the exit looked instant. Once shown it keeps its height at the end of the page; while hidden it is `inert` and ignores pointer events, so it never blocks the content behind it. Kobweb's `translateY`/`scale` set the individual CSS `translate`/`scale` properties, so transitions name those, not `transform`. The motion only runs under `prefers-reduced-motion: no-preference`), `InitialLoadingView` (the centered circular spinner lists show while loading, the web counterpart of the Android `List` loader), `FittingList` (a column that renders only the leading items whose `Modifier.fittingItem()` rows fit whole in its height, re-measured on resize, for pages that must not scroll), `Logo(description)` (the light or dark logo for the current colour mode)), typography `CssStyle`s with the `Modifier.primary()/secondary()/active()/error()` text colors (the web counterpart of mobile's `TextStyle.secondary()` etc.) and the theme. Packages: `components/` is flat like Android's; `resources/` holds localization only (`AppLanguage`, `WebLocalization`, `localized()`), as on Android; `head/` holds the page-head model and renderer (`HeadTags`, `PageMetaTags`/`HeadMeta`, `LanguageLinks`/`HeadLink`); `theme/` and `uistate/` as on mobile. Shared button timing lives in `components/ButtonMotion.kt`, used by both `StateButton` and `ButtonLink`. `BackStackHost` renders a `BackStack` with native-style screen transitions (`components/ScreenMotion.kt`): while `BackStack.transition` is set, both screens are composed, the leaving one absolutely positioned at its own scroll offset and `inert`, the new one slides in from the end (push) or the covered one slides back from the start (pop), and the window scrolls to the top on push or back to the screen's saved `BackStackEntry.scrollTop` on pop. The upper layer's `animationend` (or a timeout, immediately under `prefers-reduced-motion`) calls `finishTransition()`, which only then clears a popped entry's ViewModels. Only the current screen gets `LocalIsCurrentScreen = true`, and Telegram's `BackButton` and bottom buttons attach only for it, so the two screens never both register native handlers. Motion goes through `components/Motion.kt` (`MotionAllowed` media query, `prefersReducedMotion()`).
- `:designsystem` applies the Kobweb library plugin (`configAsKobwebLibrary()`), so Kobweb registers its top-level `CssStyle`s in both apps' generated `main.kt` and serves its `src/jsMain/resources/public/` (`logo-light.svg`, `logo-dark.svg`, `favicon.svg`, `favicon.ico`) is served at the root of both the site and the client app. Put a static file there only when both apps serve it; app-specific files stay in the app's own `public/`.
- Cards and insets inside a band take their colour from the `SurfaceCardColor`/`SurfaceInsetColor` style variables, which each band sets from `BandTone.surfaces()` (the page layout sets the `PLAIN` values as the default). Use them instead of picking `Elevated` or `Background` directly, so a card stays visible on both the plain and the alternate background.
- Split like mobile: anything reusable across pages and free of site content (no `SiteRes`, no site assets) belongs in `:designsystem`'s `jsMain` and takes its texts as `StringDesc` parameters; `:site` keeps only site-specific sections, widgets and content. Color text with `.secondary()`/`.active()` rather than `.color(ColorToken.X.themed)`.
- The Kobweb library plugin narrows the Compose compiler to JS and turns off source information and trace markers for the whole module, which on `:designsystem` breaks the Android compile (inline Compose calls fail with "couldn't find inline method"). Its `composeCompiler` block therefore sets `targetKotlinPlatforms` to `androidJvm` and `js` and turns `includeSourceInformation`/`includeTraceMarkers` back on, matching the other Compose modules. A per-module `kobweb.configureComposeCompiler=false` is not read, and the root one would drop Kobweb's tuning for the site and client too.
- Every `CssStyle` (Silk's restricted ones too, such as `InputSize` or `ButtonSize`) must be a public top-level `val` so Kobweb registers it in the app's generated `main.kt`; a private or local one throws "Failed to convert a CssStyle to a modifier" when it is first drawn, which takes the whole screen down. To tweak a Silk widget for one component, set its style variables on the modifier instead (e.g. `TextField` sets `InputVars.Height`/`Padding`/`BorderRadius`).
- Colors come from `designsystem`'s moko `colors.xml` through `theme/WebColors` (light/dark, like Android's `Colors.kt`). Resolve a `ColorToken` with `ColorToken.themed` (composable) or `ColorToken.resolve(colorMode.webColors())` inside a `CssStyle` — never hardcode a hex color in the site.
- Strings: `WebLocalization` loads one merged moko provider (the app's loader + `DesignSystem` + `CorePresentation`) inside `LocalizedContent(...)` at the app entry; render any `StringDesc` with the composable `localized()`. `AppLanguage` lists the site languages: English, Ukrainian and Polish. The site is not translated into Russian, unlike the apps, so it has no `ru` moko folders and `AppLanguage` has no Russian entry. The language comes from the URL (see **Language URLs** under Site): the layout's `@InitRoute` calls `WebLocalization.show(...)`, which sets `StringDesc.localeType` and `<html lang>`. `LanguagePicker` (a compact EN/UA/PL select) saves the choice in `localStorage` via `WebLocalization.select` and navigates to the same page in that language.
- `OptionsQuantityList(OptionsMultiPickerState)` (with `WebOptionsMultiPickerState`) lists every option inline under the picker title, each option on its own elevated card (the picked ones are not outlined); the `OptionsQuantityList(state, title, options)` overload lists a subset under its own header, so a screen can split one selection into groups (one header and its cards per service group): a `QuantityControl` per option, shown when `isEditable` and `isQuantityEditable`. It is one pill: an unpicked option shows a semibold `ActionText` "Add" (`action_add`) button on a 12% `ActionText` tint, which on its first press turns into the + icon while the − button and the count slide open to its left (− count +, 44px buttons, `OnAction` on an opaque `ButtonActive` fill), and they close again, back to the tint, when the count returns to 0. The + stays the same `<button>` throughout, so focus is kept; the pill's background colour and the − button's and the count's width and opacity transition (only under `prefers-reduced-motion: no-preference`), and while collapsed the − button and count are clipped, transparent and `inert`; the buttons scale down while pressed. It calls `onQuantityIncreaseRequested`/`onQuantityDecreaseRequested` (adding an unpicked option is an increase) and draws `DesignSystem.images.material_add`/`material_remove`.
- Not ported yet: pickers (time/date-range/money and the date picker field, and the mobile multi pickers' card with an add sheet), schedule, business menu, and a notification renderer for the browser (`WebNotificationState` exists; only the Telegram Mini App displays it, through `:library:telegram`'s `ObserveTelegramNotifications`). Add them here when a web screen needs them, together with a `Web*State`.

## Site (`:site`)

- Kobweb application module. It depends only on `:designsystem` and `:site:domcompat`: the site is static marketing and legal content with no Koin, API, database or sign-in. Anything that needs them belongs in the client web app (`:client`). Build UI from `:designsystem` web components and states rather than raw HTML/Silk styling.
- Site copy is moko strings in `apps/site/src/commonMain/moko-resources` (`SiteRes`, keys prefixed `site_` so they never collide with the shared modules' keys in the merged provider). The **No string literals in screens** rule applies to the site too, and so does **Translations**, except that the site has only `uk/` and `pl/` siblings (no `ru/`).
- `apps/site/webpack.config.d/moko-resources-inline.js` inlines moko's localization JSON into the bundle, because Kobweb's server serves only `public/` resources and the script, not webpack's emitted assets. moko regenerates `*/webpack.config.d/moko-resources-generated.js` and `*/karma.config.d/moko-resources-generated.js` on each build; they are git-ignored.
- Legal documents (privacy policy `/privacy`, terms `/terms`, data processing agreement `/dpa`) are published texts in `apps/site/legal/<document>/<version>/` (`en.md`, `uk.md`, `pl.md`, `effective-at.txt`), copied from the server repo's `docs/legal/bookkme/` with `apps/site/legal/import.sh` (see `apps/site/legal/README.md`). A published version never changes: `apps/site/legal/published.sha256` locks every file and the `generateLegalTexts` task (plugin `convention.site.legal`) fails the build when a file is edited, deleted or not locked; it also compiles the texts into `publishedLegalTexts`. `/<document>` shows the version in effect (or the first upcoming one) and `/<document>/<version>` a given version, both in the URL's language (`/uk/privacy/<version>`); the older `/<document>/<version>/<language>` URLs redirect to that form. Every page links all three languages and the version history, and links to `https://bookkme.com/...` inside a text open in the text's language. The footer lists only the privacy policy and terms; the DPA is linked from the documents themselves. The footer's description line links the public app (`bookkme-client`) and server (`bookkme`) repositories the FSL-1.1-ALv2 license and its additional self-hosting permission (`LICENSE-SELF-HOSTING.md`) (`SiteNavigation.source`).
- **Language URLs**: English lives at unprefixed paths (`/`, `/contact`); every other `AppLanguage` gets its tag as a prefix (`/uk`, `/pl/terms`), built with `AppLanguage.localize(path)` and read back with `AppLanguage.fromPath(path)`. The URL language always wins. An unprefixed URL is sent to the visitor's preferred language (saved picker choice, otherwise the browser languages) by the route interceptor in `navigation/LocalizedRoutes.kt` (`LanguageRedirect`), but not during export. Kobweb file routing only knows the English pages, so `LocalizedRoutes.kt` registers the prefixed copy of each `@Page`, and `sitePagePaths` in `apps/site/build.gradle.kts` lists the static pages for the export and the sitemap: a new page must be added to both. `apps/site/build.gradle.kts` is the source of the site's origin, page paths and languages: `generateSiteBuildConfig` (plugin `convention.site.buildconfig`) compiles them into `me.bookk.site.config.SiteBuildConfig`, `SiteNavigation.ORIGIN` reads its `ORIGIN`, and `SiteBuildConfigTest` fails when `LocalizedRoutes`' static routes or `AppLanguage` (default first) no longer match the build's lists. Internal links go through `WebLocalization.localize(path)`.
- **Page head**: `PageLayout` renders the head of every page through `HeadTags` (`:designsystem`'s `jsMain` `head/`), in a `DisposableEffect` so the tags are in the DOM in the same composition as the page and the exported HTML carries them: `document.title` (`<page title> · BookkMe`), `<meta name="description">`, `og:title`/`og:description`/`og:url`/`og:locale` (+ `og:locale:alternate`) from `PageMetaTags`, and `<link rel="canonical">` plus `rel="alternate" hreflang` for every language and `x-default` (English) from `LanguageLinks`, all against `SiteNavigation.ORIGIN`. Each page passes its title and description in `PageLayoutData` (`isFullWidth = true` drops the 64rem content column, so a page built from `Band`s can paint edge to edge; the landing pages use it) (moko strings; the description defaults to `site_description`, legal pages use `LegalDocument.description`). `PageLayoutData.notFound()` (the 404 page, and a legal URL whose version or language text is not published) emits only the description and `robots: noindex`. The page-independent tags (`og:type`, `og:site_name`, `og:image` = `/share-image.png` at 1200×630, `twitter:card`) are static in `kobweb.app.index.head`; Kobweb's global `description` is left unset so pages never carry two.
- **Sitemap and robots.txt**: `generateSitemap` (plugin `convention.site.sitemap`) writes `/sitemap.xml` and `/robots.txt` into the public resources. The sitemap lists `sitePagePaths` and every published legal version (`/<document>/<version>`: complete version folders of known documents that are listed in `apps/site/legal/published.sha256`, read once at configuration time by `LegalVersionPaths`) in every language, each with its `xhtml:link` hreflang alternates. The same `SitePages` list feeds `export { addExtraRoute(...) }`, so every legal version is exported with its own head as well. Never hand-edit either file. Both use `siteOrigin` from `apps/site/build.gradle.kts`, the same origin as the page head.
- Icons drawn on the site are Google's Material Icons (outlined, Apache License 2.0), the same set the Android app uses. They live as SVGs in `apps/site/src/commonMain/moko-resources/images/` (`material_<name>.svg`, read as `SiteRes.images.*`), or in `designsystem/src/commonMain/moko-resources/images/` (read as `DesignSystem.images.*`, so they also ship in the mobile apps' resources) when a `:designsystem` web component draws them, and are drawn with `TintedIcon` so they take a `ColorToken`. Each file is converted from the icon's `ImageVector` source in `androidx.compose.material:material-icons-extended` / `material-icons-core` (`icons/outlined/<Name>.kt`): every `materialPath` becomes one `<path>` in a 24×24 viewBox. Do not hand-draw icons.
- `/guides` is a placeholder that says the guides are coming soon and links the Contact page; the header nav links it (`SiteNavigation.GUIDES_PATH`). The Contact page stopped pointing to the guides while they're a placeholder, because the placeholder links back to Contact; add a link there again once real guides exist.
- `/.well-known/security.txt` (RFC 9116) is a static file in `src/jsMain/resources/public/.well-known/`. Its `Policy` links to the security channel on the Contact page (`/contact#security`, the `id` of each `ContactChannel`). The Kobweb server serves dot-directories from `public/` as `text/plain` in both dev and the FULLSTACK export. The `verifySecurityTxt` task (plugin `convention.site.securitytxt`) runs before `jsProcessResources`, so every site build, test run and export fails once `Expires` is less than 30 days away or more than a year ahead. Renew it by moving `Expires` up to a year ahead and redeploying.
- Icons and web app manifest: `favicon.svg` is the primary favicon; `favicon.ico` (16/32/48 px, transparent, from `favicon.svg`) is the fallback (both, and the logos they are drawn from, live in `:designsystem`'s `jsMain/resources/public/`, shared with the client app) for browsers and crawlers that ignore SVG favicons. `apple-touch-icon.png` (180 px) and the manifest icons `icon-192.png`/`icon-512.png` draw `logo-dark.svg` on `darkBackground`, like the Android launcher icon, with the glyph inside the maskable safe zone. The link preview image `share-image.png` (1200×630) draws `logo-dark.svg` on `darkBackground` with no text, so it needs no translation. They are committed files generated by `apps/site/generate-icons.sh` (it writes `favicon.ico` into `:designsystem`'s `jsMain/resources/public/` and the rest into the site's) (needs `rsvg-convert`, `brew install librsvg`); rerun it after changing a logo or `darkBackground`. `site.webmanifest` is generated at build time by `generateWebManifest` (plugin `convention.site.webmanifest`) with `lightBackground` as `theme_color`/`background_color` and the English `site_app_name`/`site_description` moko strings (read by `MokoStrings`) as its name and description. `apps/site/build.gradle.kts` reads both through `DesignSystemColors` from `designsystem`'s `colors.xml` and adds the icon, manifest and light/dark `theme-color` tags in `kobweb.app.index.head`; `faviconPath` is empty so Kobweb does not add its own icon link. Values captured by a `head.add { }` lambda must be locals, not script-level `val`s, or the configuration cache cannot store the index task.
- Kobweb version in the catalog must match the Kotlin 2.4 line. The no-comments and block-body rules apply to site code too.

## DOM API

Both Kobweb apps link against `kotlinx-browser` instead of `kotlin-dom-api-compat`. DataStore's web storage (in the client app) depends on `kotlinx-browser-js`, a full second copy of the DOM API that cannot be linked next to `dom-api-compat`. `apps/client/build.gradle.kts` and `apps/site/build.gradle.kts` therefore exclude `kotlin-dom-api-compat` and depend on `:site:domcompat`. That module adds the one symbol precompiled libraries need but `kotlinx-browser` lacks: moko-resources' `org.w3c.dom.events.EventListener(handler)` factory. Keep the factory in its own module, because a copy inside an app module creates a circular JS-module import with moko. JS links run with `-Xpartial-linkage-loglevel=ERROR`, so any other missing DOM symbol fails the build instead of the browser. When a library upgrade breaks the link, add the reported symbol to `:site:domcompat`. Upgrading moko-resources does not remove the factory: 0.27.x still calls it.
